# Smart Hospital — Data Model (ERD & Schema)

Complete relational model for the HMS, grouped by bounded context. Derived from
`Smart Hospital - PRD & FRD - New.pdf`. Target: **PostgreSQL 16** via Prisma.

## Global conventions (apply to every business table unless noted)
- `id` — `uuid` (or `bigint identity`) primary key.
- `branch_id` — FK → `branch` (multi-branch scoping; **NOT NULL** on all tenant data).
- `created_by`, `updated_by` — FK → `user` ("Generated By" in the FRD).
- `created_at`, `updated_at` — `timestamptz`.
- `deleted_at` — `timestamptz NULL` (soft delete; nothing is hard-deleted for audit).
- `custom_fields` — `jsonb` where the entity is one of the 22 custom-field targets.
- Money → `numeric(14,2)`; percentages → `numeric(5,2)`.
- Every list-facing table indexed on `(branch_id, deleted_at, created_at)` + search columns.

Legend in diagrams: `PK` primary key, `FK` foreign key, `○` nullable.

## 1. Identity, RBAC & Branch

```mermaid
erDiagram
    branch ||--o{ user : has
    role ||--o{ user : assigned
    role ||--o{ role_permission : grants
    permission ||--o{ role_permission : in
    user ||--o| staff : "is (if staff)"
    user ||--o| patient : "is (if patient)"
    branch ||--o{ branch_setting : configures

    branch { uuid id PK; string name; string code; string url; jsonb settings; bool is_home }
    role { uuid id PK; string name; string slug; bool is_system; bool protected }
    permission { uuid id PK; string module; string feature; string action "view|add|edit|delete" }
    role_permission { uuid id PK; uuid role_id FK; uuid permission_id FK; bool allowed }
    user { uuid id PK; uuid branch_id FK; uuid role_id FK; string username; string email; string phone; string password_hash; string type "staff|patient"; bool is_active }
    branch_setting { uuid id PK; uuid branch_id FK; string key; jsonb value }
```

- `permission` is seeded from the `(module, feature, action)` catalog in `packages/shared`.
- `role` seeds the 9 fixed roles (Super Admin, Admin, Accountant, Doctor, Pharmacist,
  Pathologist, Radiologist, Receptionist, Nurse) + `Patient` for the portal.
- Super Admin role is `protected = true` (Admin can view but not edit — FRD §2.31.1).

## 10. Indexing & performance notes
- Composite indexes on `(branch_id, deleted_at, created_at)` for every list screen.
- Trigram / full-text index on `patient.name`, `patient.phone`, `case_no`, `bill_no` (global search).
- Partial indexes: `bed(status) where status='available'`, `medicine(expiry) where expiry is not null`.
- Report queries hit read replicas / materialized views for the 19 report categories.
- All money mutations (invoice + payment + stock decrement) wrapped in a single DB transaction.
